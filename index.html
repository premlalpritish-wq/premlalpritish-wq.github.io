Flagship · In progress

ScaleUp AI

v0.1 · Prototype

The problem

A lot of usable process knowledge already exists — but it lives inside papers, as prose and figures, rather than as anything a machine can execute.

ScaleUp AI turns scientific literature into structured, machine-readable process knowledge. Every extracted value is traced back to a source, a page and an excerpt.

The pipeline

  1. Paper — source read with page-preserving text
  2. Extraction — page-bounded chunks, reassembly verified
  3. ProcessState — a typed, deliberately partial record
  4. ProcessGraph — operations, states, typed relations
  5. Evidence — every value traced to an excerpt
  6. Uncertainty — what is ambiguous or unreported

Scope, stated plainly. This is a demonstrable prototype, not a product surface. The reference demo data is a verified fixture rather than a live model response, and the steps beyond the extraction path are research direction. No accuracy figures are claimed.

Scientific automation · Shipped

qPCR reporting pipeline

Completed

The problem

A repetitive, error-prone laboratory workflow: raw qPCR data has to be validated, quality-checked, analysed and turned into a report — every single run.

I built an end-to-end Python pipeline that does it. The interesting part wasn't qPCR itself — it was turning the workflow into a modular system with explicit checks and reproducible output.

The pipeline

Raw data→ Parse→ Clean→ QC→ Analyse→ Visualise→ Report
  • parser.py
  • cleaner.py
  • qc.py
  • analysis.py
  • plots.py
  • reporter.py

The transferable idea. Raw input → validation → transformation → analysis → standardised output. The example dataset deliberately includes imperfect data; the pipeline flags affected results rather than presenting them as validated conclusions.

02 — Method

What if the way I approach problems is itself the product?

I don't have a successful startup to point to yet. Instead, I'm trying to build evidence that I have a repeatable way of finding and solving problems.

When I care about an outcome, I tend to turn the problem into a system: define what good looks like, find the gap between where I am and where I want to be, build a feedback loop, and iterate.

I've started deliberately documenting these experiments. The question isn't whether the method always works — it's whether it works often enough to be worth building a company around.

  1. 01 Define

    What does success actually look like?

  2. 02 Measure

    Where am I relative to that target?

  3. 03 Diagnose

    What is actually causing the gap?

  4. 04 Intervene

    What is the smallest useful change?

  5. 05 Iterate

    Did reality agree with the hypothesis?

  • 01

    Define the target.

    A vague goal makes it hard to know whether anything improved.

  • 02

    Find the gap.

    Identify the specific things preventing the transition.

  • 03

    Build a feedback loop.

    Collect information that says whether the change is working.

  • 04

    Use tools aggressively.

    AI, software, research and data compress question to answer.

  • 05

    Make small changes.

    Isolate interventions so you know what caused the change.

  • 06

    Let reality win.

    Update quickly rather than defend an idea because it was yours.
