03 SCIENTIFIC AUTOMATION COMPLETED

Automating a Scientific Workflow

Can a repetitive laboratory workflow be turned into a reproducible software system?

View on GitHub ↗ LinkedIn ↗

I built an end-to-end Python pipeline that takes raw qPCR data through validation, QC, analysis and visualization, then produces a publication-style PDF report. The interesting part wasn't qPCR itself — it was turning a repetitive, error-prone workflow into a modular system with explicit checks and reproducible output.

RAW DATA→PARSE→CLEAN→ QC→ANALYSE→VISUALISE→REPORT
QC
  • NTC contamination detection
  • Replicate variance scoring
  • Housekeeping stability checks
  • Low-confidence annotations
ANALYSIS
  • CT mean aggregation
  • ΔCT / ΔΔCT calculations
  • Fold-change computation
  • Optional bootstrap estimation
OUTPUT
  • Automated plots
  • QC tables
  • Styled PDF report
  • Optional provenance metadata
parser.pycleaner.pyqc.pyanalysis.pyplots.pyreporter.py
The transferable idea Raw input → validation → transformation → analysis → standardized output. The same architecture can be applied to other repetitive data-to-report workflows.

The example dataset intentionally includes imperfect data. The pipeline flags affected results rather than presenting them as validated biological conclusions. This is an engineering demonstration, not a diagnostic tool.

06 HOW I WORK

I don’t need to know how to do something yet. I need to be able to figure it out.

01

Define the target.

Make “better” concrete enough to measure.

02

Find the gap.

Understand what separates the current state from the target.

03

Build a feedback loop.

Get information back from the system as quickly as possible.

04

Use tools aggressively.

Software, AI, data, experts and experiments are all instruments.

05

Make small changes.

Change one important variable, observe what happens, then iterate.

06

Let reality win.

If the evidence disagrees with the hypothesis, change the hypothesis.

07 THE BET

Find problems worth becoming obsessed with.

I’m interested in technically difficult, information-heavy or poorly served problems — especially around biotech, pharma R&D, AI, industrial systems and commerce.

I don't want to force a category before finding the right problem. The longer-term bet is that someone who can systematically learn, build and iterate can eventually find something worth building at scale.
